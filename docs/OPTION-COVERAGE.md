# 被不支持选项丢弃的规则：分布与实现顺序

统计口径：直接复用编译器自己的 `parseFilterLine`，对 `filters/` 下 6 份列表逐行解析，读取 skip
原因里的选项名。解析器遇到第一个不支持的选项就返回，因此"该选项的规则数"是最小值；另用一次原始
选项串扫描给出上界，两组数字都列在这里。

扫描结果（2026-10-22）：规则行 169,113；因不支持的选项丢弃 **4,514** 条，因未知选项丢弃 **362** 条。

## 一、按选项排名（首个触发选项）

| 选项 | 拦截 | 例外 | 合计 | 能否实现 |
|---|---|---|---|---|
| `popup` | 3,011 | 51 | 3,062 | 能，走现有的 popup 守卫（见下） |
| `ghide` | 0 | 405 | 405 | 能，但对我们等于空操作 |
| `generichide` | 0 | 366 | 366 | 能，但对我们等于空操作 |
| `to` | 241 | 0 | 241 | **已实现**，映射到 `requestDomains` |
| `redirect` | 230 | 0 | 230 | 能，需随包提供替代资源 |
| `removeparam` | 216 | 6 | 222 | 能，映射到 `redirect.transform.removeParams` |
| `urlskip` | 203 | 0 | 203 | 不能，uBO 私有 |
| `redirect-rule` | 80 | 2 | 82 | 能，同 `redirect` |
| `denyallow` | 79 | 0 | 79 | **已实现**，映射到 `excludedRequestDomains` |
| `/$script`、`/$doc`、`/$image` 等 | 75 | 24 | 99 | 这是解析缺陷，不是选项缺失 |
| `csp` | 38 | 1 | 39 | 不能，DNR 没有对应能力 |
| `ipaddress`、`replace`、`rewrite`、`reason`、`method`、`permissions`、`genericblock`、`uritransform`、`popunder` | 约 100 | 约 30 | 约 130 | 多数不能 |

前 25 个选项覆盖了被丢规则的 99.6%。

## 二、四项值得做的判断依据

**1. `popup`：最大一块，而且我们已经有一半机制。**
3,011 条拦截规则，语义是"这些域名发起的弹窗一律拦掉"。AdBlow 已有 `window.open` 守卫，只需把
这些域名做成一张拒绝清单交给守卫；命中即拒绝，不依赖用户手势落点。这是单笔收益最大的一项。

**2. `to` 与 `denyallow`：320 条，实现成本最低。**
`$to=` 就是 DNR 的 `requestDomains`，`$denyallow=` 就是 `excludedRequestDomains`，两者都是一行
映射，不需要新机制。

**3. `redirect` / `redirect-rule` + `removeparam`：534 条，需要随包提供资源。**
`redirect` 要用 DNR 的 redirect 动作和随包脚本（如 `noopjs`）替换广告脚本，`removeparam` 用
`removeParams` 清除追踪参数。实现中等，但两者都是"真拦住了东西"，不是纸面覆盖。

**4. `ghide` / `generichide`：771 条，收回但不改变行为。**
这两个是"不要在该域名做通用隐藏"的例外。AdBlow 本来就不注入通用隐藏规则，所以接受它们等于
保持现状。值得做（消除"被丢弃"的噪音），但不应算作覆盖率提升。

## 三、与预算无关

这 5,194 条与静态规则预算无关：`budgetTruncated` 为 0，说明没有规则因为空间不足被丢。补完上述
选项后总规则数会从 23,278 增至约 27,200，仍在 MV3 保证的 30,000 以内，不需要提高预算。

## 四、建议顺序

1. **`to` + `denyallow`**（320 条，改动最小，先验证映射正确性）；
2. **`$popup` 拒绝清单**（3,011 条，复用现有守卫）；
3. **`redirect` / `redirect-rule` + `removeparam`**（534 条，需要随包资源与 `redirect` 动作）；
4. **修 `$` 出现在模式中的解析缺陷**（99 条，属于解析器 bug，与选项无关）；
5. `ghide` / `generichide` 作为空操作接受（771 条，行为不变，仅清理统计）。

四项做完，被丢弃的规则从 5,194 条降到约 1,230 条，其中大部分是 `urlskip` 与 `csp` 这类确实
无法映射的。

## 五、需要留意的

- 统计用的是"首个触发选项"，同时命中多个不支持选项的规则只计入一个；`redirect` 与
  `removeparam` 的共现比例未单独统计，实现时按实际解析结果为准。
- `popup` 规则多为 `@ @` 之外的拦截规则（3,011 / 3,062），把它做成拒绝清单时要注意：清单里的
  域名来自列表作者，不是 AdBlow 自己推断的。
- 这些数字随列表更新会变。以后每次刷新列表后重新跑一次统计，才能判断进度。
