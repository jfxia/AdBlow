# AdBlow 广告类型验收标准

> 本文是**有约束力的验收标准**，不是说明文档。
> 21 类「干扰视线型广告」（图片 / GIF / 视频 / 弹窗 / 跳转类，不含纯文字软文）
> 逐条对应一个可执行的浏览器实测夹具；任何一条从 PASS 退回 FAIL 都算回归。

## 怎么跑

```bash
pnpm build                                  # 必须先构建：测的是真实 dist/
node tools/e2e/acceptance.mjs               # 全部 21 类
node tools/e2e/acceptance.mjs 8             # 只测第 8 类
```

输出逐类的 PASS/FAIL、按大类的通过数、以及总命中率。

## 测量方法（为什么这个数字可信）

单靠"装扩展后看起来干净了"不算证据，所以每个夹具都跑**两遍**：

1. **基线（不装扩展）**：必须确认这一类**确实在干扰** ——
   `dom`/`hover` 类探针可见，`popup`/`click` 类确实跳转或新开标签。
   基线不复现的条目会标 `⚠️ 夹具未生效`，那说明夹具没有意义，而不是扩展做得好。
2. **装扩展**：同一夹具应被处理。

几个关键细节：

- 点击用 CDP `Input.dispatchMouseEvent` 派发 —— 它产生的是**可信事件**
  （`isTrusted === true`），与真实用户点击等价；用 JS 造事件测不出真实行为。
- 弹窗类必须带 `--disable-popup-blocking` 启动：否则"无手势 window.open"是被
  **浏览器自带拦截器**挡下的，而不是我们的守卫 —— 基线复现不了，对照失去意义。
- "新开标签数"用浏览器级 CDP 的 `Target.targetCreated` 事件统计，
  不用目标总数相减（运行期间会关掉旧页面，差值会出现负数）。
- 探针判定要求元素或其祖先带 `data-adblow-hidden`（`hideElement` 会同时打标记
  与内联 `display:none !important`），因此能区分"我们隐藏的"和"站点自己藏的"。

## 21 类逐条验收

判定所用的机制都在代码里有对应回归测试（见"测试映射"列）。

### 一、弹窗类（5/5）

| # | 类型 | 判定 | 靠什么机制 | 测试映射 |
|---|---|---|---|---|
| 1 | Pop-up 前置弹窗 | ✅ | `window.open` 守卫：**无用户手势**一律拒绝；点击劫持触发的也拦 | `guards.test.ts` |
| 2 | Pop-under 底层弹窗 | ✅ | 同上 + 持久化状态清理（`localStorage`/`sessionStorage`/`window.name`），关掉标签页也不会重弹 | `scrub.test.ts` |
| 3 | 页面浮层 Modal | ✅ | 覆盖层判定（固定/绝对 + z≥1000 + 占视口≥40% + 命名或行为旁证） | `overlay.test.ts` |
| 4 | 插屏广告 | ✅ | `interstitial` 是强命名词 —— 服务端渲染也能直接命中，不依赖快照 | `lexicon.test.ts` |
| 5 | 二次连环弹窗 | ✅ | MutationObserver 对每个新插入的浮层独立判定；内联隐藏不易被站点改回 | `content.test.ts` |

| 版本 | 命中率 |
|---|---|
| 建立验收标准时的实测（改进前） | **14/21** |
| 本轮改进后 | **21/21** |

改进前失败的 7 条与其根因：

| # | 类型 | 失败根因 |
|---|---|---|
| 8 / 18 / 21 | 随动伸缩 / 区域展开 / 富媒体扩展 | 判定只在「节点进入 DOM」时发生一次，而这类广告靠**纯 CSS 撑大**，不产生节点增删 |
| 10 | Outstream | `outstream`/`vast` 等视频广告行业术语不在词库 |
| 13 | 视频叠加浮层 | 覆盖层阈值按**视口** 40% 算，播放器内的叠加层够不到 |
| 14 | 自动展开全屏视频 | 同 8 的根因 |
| 16 | 假关闭按钮 | 完全没有判据 |

## 明确的不做（非目标）与理由

这些是**有意识的选择**，不是遗漏；改动它们需要重新评估误伤风险：

| 不做 | 理由 |
|---|---|
| **自动播放治理**（静音/暂停自动播放的视频） | 绝大多数正常站点的视频也来自跨站 CDN，"跨站即广告"一刀切会把合法视频全废。真正的骚扰点是**广告容器**，隐藏容器已经解决 |
| 把 `overlay` 加进词库 | `.overlay` / `.modal-overlay` 是合法对话框的通用类名（Bootstrap 等），且这类对话框常含跨站链接（分享、支付），收进来会误伤。视频叠加改用**几何判据** |
| 把 `video` 加进词库 | 任何视频播放器都会命中，等于隐藏全站视频 |
| 动画 / 闪烁识别 | "闪动"本身不是广告特征，按动画特征过滤会大量误伤正常动图与加载动画 |
| 拦截可见跨站链接上的真实点击 | 那会把页面上所有正常外链一起废掉。第 15 类靠"识别为广告后整体隐藏"解决 |
| 几何突增的规则**不写入自学习库** | 几何是**瞬时证据**，正常组件偶然撑大不该被固化成永久规则（`judgeGrownElement` 产出的 hit 刻意 `selector: null`） |

## 仍然存在的边界

- **夹具是我写的**：21/21 说明引擎对每一类都有对应机制，**不等于**真实站点的
  每一种实现都能抓到。真实广告的实现方式比夹具更花。
- **内联 `onclick` 与 `document.onclick` 属性赋值**不被 `addEventListener` 补丁覆盖。
- **重度混淆的源码**可以绕过基于源码文本的判据（第 19 类的识别方式）。
- **无命名的第一方素材广告**（同站图片/视频、无广告类名、无跨站链接）依旧难判 ——
  这类与正常内容在证据上无法区分，误伤代价高于收益。
- **几何巡检的基线依赖**：面积基线由 `upkeep` 在用户交互前建立。若元素在
  基线建立之前就已经撑大，这一趟检测不到（但通常会被命名/行为档拦住）。
