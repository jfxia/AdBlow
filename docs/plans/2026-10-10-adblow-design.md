# AdBlow 设计文档

> 日期：2026-10-10 · 状态：待评审 · 试点：`https://afford.gjvrohros.cc/category/jrxw1/`

**目标一句话：** 做一个不依赖任何第三方过滤列表的 Edge (MV3) 广告过滤器，靠「运行时行为检测 + 自学习规则库」在名单型屏蔽器失效的站点上也能做到广告零残留、内容零误伤。

---

## 1. 为什么 AdBlock / AdBlock Plus 在这个站点失效

这不是"规则不够全"，是**范式不匹配**。以下为 2026-10-10 实测取证结论。

### 1.1 广告是第一方自研 SSP，不是第三方广告联盟

页面内联脚本里直接暴露了广告服务配置：

```js
sspConfig: {
  appKey: "TTbLqvit...",                    // 自建 SSP 的密钥
  baseUrl: "https://apiad01.cc",            // 自研广告服务端
  cdnDomain: "https://pic.wvxrrip.cn",      // 素材 CDN
  sdkUrl: "./ad-sdk-v0.0.4.10.js"           // SDK 由站点自己托管
}
```

SDK 实体位于站点自身目录：`/usr/themes/Mirages/js/7.10.0/ad-sdk-v0.0.4.10.js`（156,995 字节，6 行压缩）。
广告竞价接口只有两个：`POST /api/sdk/ad/available` 与 `/api/sdk/ad/request`。

**含义：** 域名黑名单挡不住第一方路径。整站广告流量里，只有 `apiad01.cc` 这一个第三方域名是必需的，其余全部同源。

### 1.2 广告卡片伪装成正文卡片

广告位在服务端 HTML 里就已经是**空的正文卡占位符**：

```html
<div data-ssp-container="ssp-list" data-el-ignore>
  <div class="post-card" id="ssp-card-0" data-ssp-slot-node></div>
  <div class="post-card" id="ssp-card-1" data-ssp-slot-node></div>
  ... 共 10 个
</div>
```

而**真内容 `<article>` 与这些空占位符交错在同一个容器里**。实测该容器内真 `<article>` 节点存在，且：

- 全站带 `.post-card` 类的元素：`div` 110 个、`h2` 20 个
- 真内容的标签是 `<article itemscope itemtype="http://schema.org/BlogPosting">`，**不带** `post-card` 类

**含义：** EasyList 一类的通用外观规则不可能命中——因为类名和真内容完全撞车。任何按 `.post-card` 或 `[data-ssp-container]` 下手的规则都会把正文列表一起抹掉。

### 1.3 真正的判别信号是「运行时注入」

服务端 HTML 与 SDK 运行后的 DOM 对比（实测计数）：

| 标记 | 服务端 HTML 中出现次数 | 来源 |
|---|---|---|
| `data-ssp-container` | 2（空占位容器） | 服务端 |
| `data-ssp-slot-node` | 10（空占位） | 服务端 |
| `data-ssp-slot-root` | **0** | SDK 注入 |
| `data-ssp-sdk-popup-overlay` | **0** | SDK 注入 |
| `data-ssp-sdk-fullscreen` | **0** | SDK 注入 |
| `data-ssp-marquee*` | **0** | SDK 注入 |

SDK 会创建这些广告组件（由 SDK 内 `setAttribute` 调用与 `ssp.css` 逆向得出）：

| 组件 class | 形态 |
|---|---|
| `.xqbj-component-ssp-float-icon` | 悬浮球 |
| `.xqbj-component-ssp-popup-icon-*` | 弹窗覆盖层（图标宫格） |
| `.xqbj-component-ssp-list-card` | 信息流原生卡（伪装成帖子） |
| `.xqbj-component-ssp-horizontal-banner` | 横向横幅 |
| `.xqbj-component-ssp-icon-grid` / `-text-grid` | 图标/文字宫格 |
| `data-ssp-marquee-*` | 跑马灯广告 |
| `data-ssp-sdk-popup-overlay` / `-fullscreen` | 注入式覆盖层 |

**含义：** 「服务端快照里没有、之后凭空长出来的节点」是一个比域名名单强大得多、且不依赖站点改版的通用信号。这是 AdBlow 引擎的地基。

### 1.4 弹窗状态被持久化，关掉会自动重开

页面内联脚本中有一段自称「本地降级体系（`__AI_OPENER__` 不可用时完整替代其全部功能）」的代码，注释明确写着：

```
// 对齐：pending持久化 / 刷新重连 / 超时补偿 / beacon重试
// / pagehide beacon / visibilitychange / 充值页刷新
```

它使用 `localStorage` + `sessionStorage` + `window.name` 三处持久化弹窗状态，键名包括 `__ai_float_pending__`、`__ai_float_pending_winname__`、`__ai_float_beacon__`。

**含义：** 只拦 `window.open` 不够，状态还在，刷新就重开。必须同时清理持久化状态，并对 `pagehide` / `beforeunload` 上的 beacon 重挂做拦截。

### 1.5 站点多域名轮换 + 按访客 A/B 分流

- 实际访问域名 `afford.gjvrohros.cc`，而 canonical 指向 `https://cgw666.com/`
- JS 里存在模板占位符 `{share.aikjzz}`，说明存在域名生成机制
- A/B 实验接口 `https://api.zzlprxy.cc/api/ab-test/group` 与 `/upload`，另有 `fp.min.js`（浏览器指纹）、`ads.zyudkkup.com/api/eventTracking/report.json`（归因上报）、Yandex Metrica、Google Tag Manager

**含义：** A/B 分流意味着**同一个站在不同访客看到的 DOM 结构不同**。任何写死的选择器都会对一部分访客失效。这从另一个角度证明了必须做行为检测 + 自学习，而不是维护静态规则。

## 2. 两个必须锁死的误伤风险

误伤比漏拦更严重——漏拦只是有广告，误伤是网站不能用。

### 风险 A：`pic.wvxrrip.cn` 不是纯广告域名 ⛔

它同时是 SSP 的素材 CDN **和**正文缩略图 CDN。服务端 HTML 中有 31 处引用，由主题函数直接绑定到真实帖子：

```js
loadBannerDirect('https://pic.wvxrrip.cn/upload_01/xiao/20261008/2026100822150350723.jpeg',
                 '', document.querySelector('#post-card-137924'), '-1', ...)
```

**结论：禁止把 `pic.wvxrrip.cn` 加入网络拦截。** 正确做法是拦 `apiad01.cc` 的竞价接口并拦掉 SDK 本身——没有竞价就没有素材请求，素材域名自然不会被访问，无需冒险拉黑。

### 风险 B：`.post-card` 与 `[data-ssp-container]` 都不能直接隐藏 ⛔

见 1.2。可安全使用的判别锚点只有：

- `[data-ssp-slot-node]`（空占位符）
- `[id^="ssp-card-"]`
- `[data-ssp-slot-root]`、`[data-ssp-sdk-popup-overlay]`、`[data-ssp-sdk-fullscreen]`、`[data-ssp-marquee]`、`[data-ssp-landing]`（SDK 注入）
- `.xqbj-component-ssp-*`（SDK 组件）

**这两条风险都要写成自动化断言测试**，任何后续改动若违反就红。

## 2.5 启发式的实测标定（决定了「快照回填」是必需品，不是优化）

在真实页面的脱敏快照（1023 个元素）上逐元素打分，得到两条硬结论。

### 结论一：后代信号绝不能无条件聚合

早期实现对整棵子树聚合跨站链接，结果：

| 元素 | 得分 | 原因 |
|---|---|---|
| `<html>` | **20** | 累加了整页所有跨站链接 |
| `<body>` | **20** | 同上 |
| `<footer>` | 12 | 同上 |
| `div.container` | 12 | 同上 |

盒子越大分越高——一旦过阈值就是**整页消失**。这不是阈值问题，是模型问题。
修正后改为「后代信号只在元素紧凑（后代 ≤ 12 个元素）时才计入」，`<html>`/`<body>`
直接降到 **0 分**，服务端内容最高分从 20 降到 8。

### 结论二：即使修好聚合，服务端内容仍会过阈值

修正后仍有三个**服务端渲染的合法元素**得 8 分（跨站链接）：

| 元素 | 得分 | 实际是什么 |
|---|---|---|
| `div.contact-link` | 8 | 联系方式（Telegram / Twitter / QQ 外链） |
| `footer#footer` | 8 | 页脚社交链接 |
| `div.container` | 8 | 页脚容器 |

阈值 6 会误伤这三处；把阈值抬到 10 可以躲开，但会同时丢掉
「跨站链接 + 推广参数 = 6」这条**最有价值的通用检测能力**（它不依赖任何词库，
是「不用第三方列表也能通用」的核心机制）。

### 由此确立的架构约束

**启发式只能作用于「已确认由脚本注入」的节点，而这需要一份完整的服务端快照。**

而 `document_start` 时页面才刚开始解析，就地取的快照几乎为空、不可信。因此必须有
一条**快照回填通道**：由 service worker 额外抓一次该 URL，内容脚本用 `DOMParser`
解析后建立签名索引。代价是未知站点**每页多一次同源请求**（试点站 HTML 约 189KB）。

工程取舍（已在代码中实现）：

| 情形 | 行为 | 理由 |
|---|---|---|
| 站点命中规则包 | 不回填，启发式关闭 | 已有精确锚点，不需要付带宽代价（试点站属此类） |
| 站点无规则包 | 回填，启发式启用 | 这是通用性的来源，值得付一次请求 |
| 回填失败 | 退化为仅静态规则 | 静态规则不依赖快照，仍安全 |

这条约束是硬约束：**快照不可信时启发式整体关闭**，宁可少拦也不误伤。

## 2.6 第二站点取证：暴露出的通用性缺陷（2026-10-10，用户反馈驱动）

用户反馈「换了个网站（1024cg.com）就拦不住了」。取证后发现**两个真实缺陷**，
其中一个是架构级的，不是规则不够多。

### 缺陷一：词库用子串匹配 + 词表太小

旧实现把 class/id 拼成一个字符串做**子串**匹配，且词表只有十几个词。
结果第二站点最直白的命名**一个都认不出**：

| 命名 | 旧实现 | 说明 |
|---|---|---|
| `class="ad-item"` | 漏 | 连整词 `ad` 都不在词表里 |
| `class="ads-title"` | 漏 | — |
| `class="post-card-ads"` | 漏 | — |
| `id="ad-card-0"` | 漏 | — |

修正为**整词分档**匹配：按非字母数字切词，只认独立词，因此
`download` / `header` / `thread` / `shadow` / `gradient` / `adaptive` 这些含
"ad" 字母的正常词不会被误判，而 `ad-card-0` → `['ad','card','0']` 能命中。
词分三档（见 `src/engine/lexicon.ts`）：取证标记 > 强命名 > 弱命名。

### 缺陷二（架构级）：判定只有「脚本注入」一档

旧判定要求「必须是运行时注入的节点」才跑启发式。这条约束是**试点站标定出来的**
（§2.5 的三个高分服务端元素），但第二站点的广告**本身就是服务端渲染的**：

```html
<article class="ad-item">…恰好 1 个跨站链接，无 BlogPosting 标记…</article>
<div class="post-card" id="ad-card-0">…</div>   <!-- ad 在 id 里，不在 class -->
```

于是所有广告被那道闸门排除在外，一个都拦不住。**这说明原设计的通用性建立在
「广告都是脚本注入的」这个未经检验的假设上。**

修正为**三档决策，证据强度递减**：

| 档 | 条件 | 依据 |
|---|---|---|
| ① 命名档 | 强广告命名 | 确定性证据，不看注入时机、不看行为 |
| ② 弱命名 + 行为 | `banner`/`popup`/`float` 等 + 跨站外链 | 弱词需旁证 |
| ③ 纯行为档 | 无命名线索，且**必须**是脚本注入 | 间接证据，需注入佐证（§2.5 的约束仍然成立） |

### 加命名档时自己踩出的事故（已写成回归断言）

命名档上线后立刻误伤了试点站：`<div data-ssp-container="ssp-list">` 的属性名含
`data-ssp-`，被判成强命名，**整个正文列表被隐藏**——正是 §2 反复强调的那条红线。

由此确立一条优先级高于所有证据的规则：

> **内容守卫**：任何包含真实正文标记（`article[itemtype*="BlogPosting"]`、
> `[itemprop="articleBody"]` 等）的元素，一律不因命名或行为被隐藏。
> 命名证据再强，也不能推翻「这里面装着正文」这个事实。

### 修正后的双站点实测（真实 Edge，headless）

| | 试点站 | 1024cg.com |
|---|---|---|
| 站点规则包 | 有（但页面已轮换到新域名，实际未命中） | **无** |
| 广告元素可见 | 21/21 → **0/21** | 64/64 → **0/64** |
| 正文可见 | 20/20 → **20/20** | 20/20 → **20/20** |
| 广告基础设施请求成功 | 2 → **0** | 无可安全拉黑的端点 |
| 隐藏元素合计 | 41 | 107 |

顺带验证了域名轮换：试点站本次实际落在 `abc.nplnjzpc.cc`，规则包未命中
（`规则包=0`），但通用路径仍然把 21 个广告元素全部清掉 —— 这是通用性的直接证据。

## 2.7 第三轮：让未知站点也拿到网络层保护（自学习闭环）

用户反馈的第二层意思更重要：**「如果每遇到一个新网站都要改程序，这个扩展就没有存在必要」**。
这一轮针对「还需要靠人改代码」的地方动手。

### 缺陷：未知站点完全没有网络层保护

此前 DNR 规则**只来自内置站点规则包**，所以第二站点（无规则包）只受 DOM 层保护：
广告看不见了，但请求照发（带宽、追踪、弹窗跳转都不受影响）。

### 机制：从行为里学出广告域名

1. 被隐藏的广告元素所引用的跨站域名 → 记录（累计 3 次晋级）
2. 晋级的域名 → 编译成 DNR 拦截规则（`||domain^`），全局生效
3. 全程零配置；options 页面提供可选的人工审阅入口

**为什么把外链也算进去**：广告卡常用跨站**链接**（点击目标）而不是资源加载。
拦截子资源并不影响 `<a href>` 导航（DNR 规则刻意排除 `main_frame`），
所以学落地页域名既安全又能挡住弹窗与强制跳转。

### 三道硬性安全过滤（各配一条回归测试）

| 过滤 | 不这么做会怎样 | 实测依据 |
|---|---|---|
| 排除**也被可见内容使用**的域名 | 正文缩略图全废（风险 A） | `pic.wvxrrip.cn` 既是广告素材 CDN 又是正文图 CDN |
| 排除**站点自有域名**（canonical / og / 图标） | 镜像域名被学成广告域名，正文图全废 | 试点站 canonical 指向 `cgw666.com`，而它托管正文图 |
| 排除**裸 IP** | 生成 `||219.76^` 这类会误配的规则 | 站点把上报放在 `https://54.169.219.76:15212/`，按末两段取域名会截断 |

另外：`main_frame` 永不拦截（否则用户主动点击会直接导航失败）；用户手动关掉的站点
通过 `excludedInitiatorDomains` 豁免，保证「关掉本站」在网络层也生效。

### ⚠️ 事故：自学习把内容图 CDN 学成了拦截域名（用户反馈驱动）

用户反馈「1024cg 首页**所有图片都不显示**」。根因是自学习闭环：

| 步骤 | 发生了什么 |
|---|---|
| 1 | 该站的内容缩略图与广告素材**共用同一个 CDN**（`pic.jtzatly.cn`，与试点站的 `pic.wvxrrip.cn` 同一模式） |
| 2 | 内容缩略图是**懒加载**的，检查「该域名是否被可见内容使用」时它的 `src`/`data-src` 还没填上 |
| 3 | 于是该域名被当成「被隐藏广告独占」，累积 3 次后晋级为 DNR 拦截规则 |
| 4 | 网络层把该 CDN 全部拦掉 → **整站图片消失** |

**教训：靠「可见性快照」判断域名归属会被时序骗过。** 修法是两条**结构性**保证，
都不再依赖任何时序判断：

1. **自学习规则永不拦 `image` / `media`。** 拦广告的价值主要在
   `script` / `sub_frame` / `xmlhttprequest`（广告 SDK、追踪、弹窗），
   图片本身收益小、风险大。这条保证让「自学习把页面图片弄坏」在物理上不可能。
2. **只要某域名在本页任何位置充当过图片/视频来源，就绝不学它**（不论可见与否）。
   媒体 CDN 在广告与内容之间共用太常见，一律不学。

同时补上了此前**空转的检测盲区**：E2E 原先用 `article[...] img` 作正文图选择器，
而该站的图片根本不在 `article` 里 → 匹配数为 0 → 断言被 `total === 0` 跳过
（**守卫匹配不到东西时是"静默通过"的**）。现在改成站点无关的度量：
被隐藏图片必须全部位于取证确认的广告位内、图片加载率不低于基线、
被拦图片请求数必须为 0。

**实测验证**：两站 `图片请求被拦 0 个`；1024cg 连续 3 次访问
`图片 27/27 → 27/27 → 27/27` 全部正常加载；被隐藏的图片全部位于广告位内
（试点站 10/17、1024cg 21/25，**广告位外 0 张**）。

### ⚠️⚠️ 事故二：自学习**选择器**把内容整片隐藏（同一位用户再次反馈）

修完网络层后用户反馈「所有图片**还是**都被屏蔽」。这次是 DOM 层，而且更隐蔽：

| 步骤 | 发生了什么 |
|---|---|
| 1 | 自学习从被隐藏元素推导出选择器，**直接写进 `document_start` 注入的样式表** |
| 2 | 那条路径**没有任何元素级守卫** —— 而规则包的护栏 `validateSitePack` 只管规则包，管不到自学习结果 |
| 3 | 于是学到 `.post-card`（正文卡片类名，正是规则包明令禁止的选择器）与 `.tjtagmanager`（站点通用外链包装类，命中 43 个元素、内含 22 张图） |
| 4 | 该站的内容缩略图**不是 `<img>`，而是设在帖子卡片上的 CSS 背景图**（与试点站 `loadBannerDirect` 同一手法）→ 卡片一被隐藏，用户看到的就是「所有图片都不显示」 |

**为什么前两轮都没抓到**：所有 E2E 都用**全新 profile**，没有累积的学习结果，
所以「学出来的选择器造成误伤」这一类问题在测试里**结构性地不会出现**。
这是验证方法本身的盲区，比单个 bug 更值得记下来。

修法（多层，且每层都有回归测试）：

1. **自学习选择器绝不进样式表。** 选择器集合拆成 `curated`（规则包，经取证与
   fixture 回归测试，可进样式表）与 `learned`（自动推导，只走带守卫的逐元素判定）。
2. **入库前四道闸门**：复用规则包的禁用选择器判定（挡住 `.post-card`）；
   命中元素不得含正文；**命中元素含图片总数 ≤ 4**（挡住 `.tjtagmanager` 的 22 张，
   同时放过只含 1–2 张素材图的正常广告位）；命中数上限。
3. **自学习选择器不授予「无条件隐藏」特权**：它只免去「必须证明是脚本注入」
   这一步，仍要求元素自带命名或行为证据。
4. **全局不变量**：任何来源的选择器都不得隐藏装着正文的元素。
5. **一次性数据迁移**：安全闸门只能防将来，管不了用户浏览器里的历史数据。
   版本号一变即清空全部自学习结果并重学。

同时新增了专门的验证工具 `tools/e2e/diagnose-selectors.mjs`：**连续访问以累积学习结果**，
然后检查每条晋级选择器会命中多少图片、内容卡片是否被隐藏。
这类 bug 从此有了对应的测试形态。

另外修掉一个 eigenen 度量的假阳性：可见性判断原先只看元素自身，
而位于已隐藏容器内、且自身是 `fixed/absolute` 的元素会被误判为"可见"
（它们的 `offsetParent` 本来就是 null）。现在沿祖先链检查 display/visibility。

### §2.9 点击劫持防护（用户反馈驱动的第五轮）

用户反馈：某站「页面加载后随便点哪里都会跳到别的网站」。这是与前四轮完全不同的
一类攻击 —— 不隐藏内容、不发额外请求，而是**劫持用户的鼠标点击**。

三种真实手法与对应防线：

| 手法 | 为什么之前的防护都无效 | 防线 |
|---|---|---|
| 覆盖一个**看不见的全屏层**（`position:fixed;inset:0;opacity:0;z-index` 极高，内含跨站链接） | `window.open` 守卫会因「有用户手势」而放行（这里用的正是真实点击）；覆盖层检测要求有可见内容或命名证据，而它两者都没有 | ① 主动隐藏「铺满视口 + 高层级 + 渲染不出任何可见内容」的元素；② 捕获相点击拦截兜底 |
| **文档级点击处理函数**直接改 `location.href` | 点击目标是**正常内容**，拦事件就等于拦正常点击；而 `location.href` 的赋值本身**无法被拦截** | 在**注册时**拒绝「文档级 + 源码里确实做导航操作」的点击监听器 |
| 脚本**合成一个隐藏的跨站 `<a>`** 再 `.click()` | 合成点击也是 click 事件，看起来一样 | 用 `isTrusted === false` 识别，并要求跨站 + 链接不可见 |

**隐形层判定的安全性来自一条性质**：一个铺满视口、层级很高、却渲染不出任何可见
内容的元素，隐藏它在**视觉上是零影响** —— 因为它本来就什么都看不见。
所以这条规则几乎没有误伤代价，却能掐断整个通路的入口。

**「注册时拒绝」的必要性**：`location.href` 的赋值无法拦截，因此只能从源头下手。
判据只看**导航操作本身**（赋值或调用 `assign`/`replace`、`window.open`），
不看是否提到 `location` —— 否则会误伤 SPA 路由（它们常在文档级监听器里读
`location.pathname` 并 `history.pushState`，那是正常行为）。

### 验证方式：受控夹具 + 基线对照

点击劫持无法用「元素是否被隐藏」来验证，只能用**行为**验证：
加载页面 → 用 CDP `Input.dispatchMouseEvent` 派发**可信**点击（`isTrusted === true`，
与真实用户点击等价）→ 检查 URL 是否改变、是否开了新标签。

`tools/e2e/clickjack.mjs` 提供三种手法的本地测试页，并**先跑不装扩展的基线**：

```
基线（不装扩展）：三种手法全部跳转        ← 证明夹具确实有效
装扩展后        ：三种手法全部被拦住，0 个新标签
```

**诚实的边界**：在用户报告的那个真实站点上，**基线（不装扩展）也没有复现跳转** ——
该站点的劫持在此测试环境下不触发（可能依赖真实用户行为、特定广告加载或地区定向）。
因此**无法据此判断扩展是否真的修好了那个站点**；能证明的是机制本身有效。
工具在这种情况下输出 `SKIP/结论不确定`，而不是 `FAIL` —— 那不该算扩展的问题。

### 仍然存在的边界（点击劫持）

- **内联 `onclick="location.href=…"` 与 `document.onclick = fn` 属性赋值不被覆盖** ——
  两者都绕过了 `addEventListener` 补丁。这类写法在劫持代码里比 `addEventListener` 少见，
  但不是没有。
- **代码混淆可绕过**：判据基于源码文本的正则匹配，重度混淆（如把 `location` 拆成
  字符串拼接）可能躲开。
- **拒绝文档级导航监听器会影响"真这么写"的站点**。正常站点用 `<a href>` 或 History API，
  因此接受这个代价；但这是本轮最可能引起功能异常的一处取舍。
- **不可见跨站合成点击的拦截**也可能挡掉少数程序化下载流程（要求链接不可见才拦，
  已尽量减少影响）。

### 实测：扩展在自己变好（1024cg.com，真实 Edge，连续 3 次访问）

| | 自学习选择器 | 隐藏构成 | 已拦截域名 | DNR 规则 |
|---|---|---|---|---|
| 访问 1 | 0 | rule=0, **heuristic=106** | 19 | 7 → 26 |
| 访问 2 | 1 | rule=41, heuristic=87 | 20 | 27 |
| 访问 3 | 3 | **rule=104**, heuristic=23 | 20 | 27 |

第 1 次全靠启发式判定；第 3 次绝大部分已由**它自己学到的规则**接管。
这就是「未知站点不需要人工介入也会变好」的实现。

### 这一轮又踩到的三个坑（都写成了断言）

1. **覆盖层检测必须独立成一趟。** 一开始把 `getComputedStyle` 塞进逐元素打分，
   而扫描过程又不断改内联样式（隐藏元素）→ 样式/布局反复失效 →
   大页面上整趟扫描跑不完。症状是「样式表注入了，但一个元素都没隐藏」。
   现在先用 `[style*="position"]` 廉价预筛，只对极少数候选测几何。
2. **可选增强绝不能阻塞核心收尾。** 收尾工作（覆盖层、域名学习、统计）原先排在
   `await 快照回填` 之后，回填偶发不返回就直接把收尾全堵死（症状：元素隐藏了，
   却没打印就绪日志、一个域名都没记）。现在收尾独立进行，回填带 6s 超时。
3. **`registrableDomain` 对 IP 是错的。** `54.169.219.76` 取末两段得到 `219.76`，
   会生成误配规则。IP 字面量现已原样返回，且不参与学习。

### 仍然存在、且不会靠这一轮消失的限制

- **启发式仍需一次服务端快照回填**（未知站点每页多一次同源请求）。回填失败则
  退化为「静态规则 + 命名档 + 自学习域名」，纯行为档关闭。
- **iframe 广告只作为贡献信号**（跨站 iframe +4），不单独判定 —— 视频/地图/评论
  都是跨站 iframe，误伤代价太高。这类广告主要靠命名档（AdSense 的
  `adsbygoogle`、GAM 的 `google_ads_iframe_*` 都命名词库）与学到的域名。
- **主动对抗型站点**（检测到扩展后改用第一方路径投放、或渲染成纯图片）仍可能绕过。
- **A/B 分流变体未穷尽。**
- **个别空广告位可能不被隐藏**：若某个广告位既无命名线索、又没有任何跨站链接/
  媒体（例如未售出的占位），判定器不会动它。实测 1024cg 上偶发 1 个
  `div.horizontal-banner` 属于这种情况 —— 它没有可见广告内容，属可接受残留。

## 3. 架构：四层引擎

```
                    ┌──────────────────────────────────────────┐
   document_start   │ L4 注入层 (MAIN world)                    │
                    │   window.open 守卫 / 持久化状态清理        │
                    │   pagehide·beforeunload beacon 拦截       │
                    ├──────────────────────────────────────────┤
                    │ L2 外观层 (ISOLATED world)                │
                    │   静态站点规则包 + 已学习规则（USER CSS）  │
                    ├──────────────────────────────────────────┤
                    │ L3 行为层 (ISOLATED world)                │
                    │   服务端快照 diff → 广告度打分 → 隐藏      │
                    │   → 选择器泛化 → 自学习入库                │
                    └──────────────────────────────────────────┘
                                     ↕ 消息
                    ┌──────────────────────────────────────────┐
                    │ Background Service Worker                │
                    │   站点规则包加载 / DNR 动态规则同步        │
                    │   规则库存储 / 统计                        │
                    └──────────────────────────────────────────┘
                                     ↕
                    ┌──────────────────────────────────────────┐
   network           │ L1 网络层  declarativeNetRequest          │
                    │   广告服务接口 + SDK 脚本 + 追踪端点       │
                    └──────────────────────────────────────────┘
```

### L1 网络层 —— declarativeNetRequest

MV3 已无阻塞式 `webRequest`，网络拦截只能走 DNR。规则两类：

1. **广告基础设施**（高风险，需逐条取证后加入）
   - `||apiad01.cc^`（竞价接口，这是唯一必需的第三方域名）
   - `*/ad-sdk-v*.js`（**单条收益最高的规则**：SDK 不加载则广告组件根本不生成）
   - `||ads.zyudkkup.com^`、`||api.zzlprxy.cc^`、`||wj-api-abtest.yvyjdhr.com^`（归因与 A/B）
   - `||mc.yandex.ru^`、`||googletagmanager.com^`（第三方统计）
2. **第一方路径规则**（不拉黑域名，只拦路径，避免风险 A）

静态规则集写进 manifest，站点级学习规则用 `updateDynamicRules` 热更新。所有规则带 `priority`，并给用户站点级开关留 `allowAllRequests` 白名单出口。

### L2 外观层 —— 精准隐藏，绝不碰容器

- 用 `chrome.scripting.insertCSS({ origin: 'USER' })`：USER 源样式**天然压过作者样式**，不必靠 `!important` 打价格战，也不容易被站点用 `!important` 反制。
- 静态 CSS 在 manifest 的 `content_scripts.css` 里声明，保证 `document_start` 就位，无闪白。
- 空占位符要**塌陷**而不只是隐藏：`[data-ssp-slot-node]:empty { display:none; height:0; margin:0; padding:0; }`，否则拦了 SDK 会在列表里留一排空洞。
- 硬约束（写成测试）：规则集内**禁止**出现 `[data-ssp-container]`、裸 `.post-card`、`pic.wvxrrip.cn`。

### L3 行为层 —— 通用性的来源

这是「不用第三方列表也能通吃」的关键。

**a. 服务端快照 diff.** `document_start` 时遍历 DOM，记录每个节点的「标签 + 稳定属性哈希」，得到 `PristineIndex`。之后任何 MutationObserver 捕捉到的新增节点，若不在索引里，即候选注入节点。

**b. 广告度打分.** 对候选节点算 `score` 与 `reasons[]`，特征全部自研：

| 特征 | 权重 | 说明 |
|---|---|---|
| 自研广告词库命中（class/id/属性） | 高 | `ssp`/`advert`/`ad-slot`/`guanggao`/`sponsor`/`popunder` 等，词库自己维护 |
| 出站链接指向**不同可注册域名** | 高 | 正文不会把主链接指向别的站 |
| 链接带推广参数 | 中 | `utm_`/`click_id`/`aff`/`invite`/`channel` |
| `position:fixed/absolute` + 高 `z-index` + 覆盖视口比例 | 高 | 悬浮球/覆盖层 |
| 媒体资源跨可注册域名 | 中 | 正文图通常同源或已知 CDN |
| 无 `<article>`/长文本，但占位面积大 | 中 | 空壳大盒子 |
| 同构兄弟节点重复出现 | 中 | 宫格/跑马灯 |
| **跨页面重复出现** | 高 | 正文不会在每个页面都冒出来，广告会 |

**c. 选择器泛化.** 命中后把节点选择器「去易变化」：`id="ssp-card-3"` → `[id^="ssp-card-"]`；丢掉随机哈希类名；优先稳定属性路径；正确转义。产出可复用规则而非一次性指纹。

**d. 自学习闭环.** 泛化后的规则按站点存入 `chrome.storage.local`，下次访问在 `document_start` 直接应用（无闪烁）。这是「完全自研不用第三方列表」路线下规则库的增长方式——**规则由引擎自己长出来**，并且可在选项页人工审阅/导出/回滚。为了避免自学习污染，规则入库需连续 N 次命中同一泛化选择器才提升为持久规则，且提供一键撤销。

### L4 注入层 —— 激进对抗

在 MAIN world 于 `document_start` 注入：

- **`window.open` 守卫**：`Object.defineProperty` 包裹，只放行同可注册域名且用户手势触发的调用。
- **持久化状态清理**：按模式清理 `localStorage`/`sessionStorage`/`window.name` 中的 `__ai_float_pending__`、`__ai_float_beacon__` 等键。
- **beacon 重挂拦截**：`EventTarget.prototype.addEventListener` 守卫，阻断 `pagehide`/`beforeunload` 上注册的广告 beacon。
- **反屏蔽诱饵中和**：自研的少量 scriptlet（不引入第三方脚本库）。

## 4. 关键实现取舍

| 决策 | 选择 | 理由 |
|---|---|---|
| 过滤列表 | **完全自研**（用户决定） | 无订阅依赖；代价是普通站点初期覆盖弱，靠 L3 自学习补齐 |
| 隐藏样式来源 | `insertCSS` + `origin:'USER'` | 天然压制作者样式，避免 `!important` 拉锯 |
| 注入世界 | ISOLATED 做检测，MAIN 做对抗 | 检测逻辑需要隔离保护；对抗 `window.open` 必须在 MAIN |
| 框架 | Rollup + 自研 15 行 TS 转换插件，UI 用原生 TS | Vite/Vitest 在本沙箱不可用（见 §5）；`@rollup/plugin-typescript` 会按 tsconfig 的 `include` 过滤，也踩坑。自研插件不经过 tsc 的 emit 校验，因而允许 `.ts` 后缀导入 |
| 交付形态 | 先开发者模式加载未打包 | 立即可用；代码结构保持上架 Edge 商店的合规性 |

**非目标（v1 不做）：** 第三方列表语法兼容、CNAME 反伪装、移动端、云同步规则、多浏览器（Firefox）适配。

## 5. 测试架构（受沙箱约束）

实测：当前沙箱**禁止命名管道**，Chromium 的 Mojo IPC 起不来，启动 Edge 直接
`FATAL: mojo/public/cpp/platform/platform_channel.cc: Check failed: 拒绝访问 (0x5)`。
因此浏览器 E2E 在本会话受限模式下**不可能**运行。

同一个限制还干掉了两个看似无害的工具（实测，勿再尝试）：

- **Vite / Vitest 完全不可用。** Vite 在 Windows 上会调 `exec('net use')` 探测网络驱动器
  （`optimizeSafeRealPathSync`），该 `exec` 因管道受限抛 `spawn EPERM`，
  且发生在**配置加载阶段**——所以 `vite build` 和 `vitest run` 都跑不起来。
  它先尝试的 `fs.realpathSync.native` 在正常目录上不会抛特定错误，因此无法绕过。
- **`node --test` 也不可用**，因为它会为每个测试文件 spawn 子进程。
  替代方案是**直接 `node tests/run-all.ts`**（进程内执行，零 spawn）。

注意边界：受限的是**子进程管道**，不是原生插件加载。所以 Rollup（纯 JS + 原生 addon）
可用——这一点已实测验证。

据此分三层，把绝大部分验证压进沙箱内：

| 层级 | 内容 | 是否需要放宽沙箱 |
|---|---|---|
| **T1 纯单元** | 快照 diff、打分器、选择器泛化、规则编译、状态清理规划 | 否，沙箱内 Vitest |
| **T2 仿真集成** | 用 jsdom + 真实抓取的页面 HTML / SDK 文件做 fixture 回放 | 否，沙箱内 Vitest + jsdom |
| **T3 浏览器 E2E** | CDP 驱动已装 Edge 155 加载未打包扩展，真实访问试点站 | **是**，申请一次性完全权限 |

T3 的骨架已在 `_probe/cdp-probe.mjs` 验证过连通方式（`--load-extension` + `/json/list` + WebSocket CDP，零依赖，Node 24 内置 `fetch`/`WebSocket`）。E2E 断言必须包含**误伤守卫**：

1. 对广告域名的请求数 = 0
2. `[data-ssp-slot-node]` 渲染出的广告内容 = 0
3. **真 `<article>` 可见数量 与 基线一致**（误伤守卫，最关键）
4. 未产生 `window.open` 弹窗
5. `pic.wvxrrip.cn` 的正文图片仍能正常加载（误伤守卫）

### 仍然存在的残余风险（据实记录）

1. **A/B 分流变体未穷尽**（第 5 项）。若某变体把广告容器与正文容器合并，静态规则
   需要按页面形态细分。缓解：规则包受误伤护栏约束，且自学习可逐条撤销。
2. **快照回填的带宽代价**：无规则包的站点每页多一次同源请求。v1 的策略是
   「命中规则包就不回填」，因此试点站不付这个代价；普通站点要付。
3. **`pic.wvxrrip.cn` 的双重身份**是全局约束：它既是 SSP 素材 CDN 又是正文缩略图
   CDN，任何情况下都不能整体拉黑。已写成回归断言（`validateSitePack` + 单测）。
4. **MAIN world 的 `Object.defineProperty(window, 'open')` 是强干预**：站点若用
   iframe 或 `location.assign` 绕过，当前实现拦不住。v1 只覆盖 `window.open`，
   其余依赖静态/启发式隐藏。
